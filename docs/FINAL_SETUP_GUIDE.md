## 2. Credentials and config the repository does NOT contain

These must be supplied by you. **Never commit them.**

### 2.1 Firebase (backend + Flutter)

Create a Firebase project, enable Email/Password auth, and create a Firestore database in Native mode.

| Item | Where to find it | Where it goes |
| --- | --- | --- |
| `FIREBASE_PROJECT_ID` | Firebase console → Project settings → General | Render env (backend) |
| `FIREBASE_SERVICE_ACCOUNT_B64` | Firebase console → Project settings → Service accounts → **Generate new private key** → base64-encode the entire JSON file (`base64 -w0 service-account.json`) | Render env (backend) |
| Firebase Web config (`apiKey`, `appId`, `messagingSenderId`, `projectId`, `storageBucket`, `authDomain`) | Firebase console → Project settings → General → Your apps → Web app | `flutter_app/lib/firebase_options.dart` (generated by FlutterFire CLI — see `docs/FIREBASE_SETUP.md`) |
| `google-services.json` | Firebase console → Project settings → General → Your apps → Android app | `flutter_app/android/app/google-services.json` (gitignored) |

### 2.2 Supabase (file storage only — not the database)

Create a Supabase project and a **private** bucket called `ekthikana-files` (or another name you choose).

| Item | Where to find it | Where it goes |
| --- | --- | --- |
| `SUPABASE_URL` | Supabase dashboard → Project → Settings → API → Project URL | Render env |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase dashboard → Project → Settings → API → **service_role** (secret) | Render env (server-only; never expose to Flutter) |
| `SUPABASE_BUCKET` | Name of the private bucket you created | Render env (defaults to `ekthikana-files`) |

### 2.3 Gemini (Study AI)

| Item | Where to find it | Where it goes |
| --- | --- | --- |
| `GEMINI_API_KEY` | https://aistudio.google.com/app/apikey → Create API key | Render env |
| `GEMINI_MODEL` | Default is `gemini-3.7-flash`; only override if Google publishes a newer stable name | Render env |

### 2.4 Render (backend deploy)

| Item | Where to find it | Where it goes |
| --- | --- | --- |
| `BACKEND_BASE_URL` | Render dashboard → your service → URL (e.g. `https://ekthikana-api.onrender.com`) | `flutter_app/lib/core/app_config.dart` (ClientConfig.apiBaseUrl) |
| `CORS_ORIGINS` | Comma-separated list of allowed origins; leave empty for same-origin only | Render env |
| `ALLOWED_EMAIL_DOMAINS` (optional) | If you want to restrict registration to specific domains (e.g. `university.edu`) | Render env |

## 3. Render environment variables (single source of truth)

In Render → your service → **Environment**, add exactly these:

```text
FIREBASE_PROJECT_ID              = <your firebase project id>
FIREBASE_SERVICE_ACCOUNT_B64     = <base64 of service-account.json>
SUPABASE_URL                     = https://<your-project>.supabase.co
SUPABASE_SERVICE_ROLE_KEY        = <service_role secret>
SUPABASE_BUCKET                  = ekthikana-files
GEMINI_API_KEY                   = <gemini api key>
GEMINI_MODEL                     = gemini-3.7-flash
CORS_ORIGINS                     =
SIGNED_URL_TTL_SECONDS           = 900
MAX_UPLOAD_BYTES                 = 15728640
MAX_USER_STORAGE_BYTES           = 104857600
MAX_UPLOADS_PER_DAY              = 10
MAX_AI_PER_DAY                   = 30
PORT                             = 10000
```

Render auto-injects `PORT`. The other values match `backend/app/core/config.py` defaults — only the secrets and IDs above need to be filled.

## 4. Flutter-side configuration

1. Install Flutter (≥ 3.38) and follow `docs/ANDROID_SETUP.md`.
2. Install the FlutterFire CLI: `dart pub global activate flutterfire_cli`.
3. From `flutter_app/`, run `flutterfire configure` and select your Firebase project + Android app. This regenerates `lib/firebase_options.dart` with real Web config.
4. Place your `google-services.json` at `flutter_app/android/app/google-services.json`.
5. In `flutter_app/lib/core/app_config.dart`, set the API base URL to your Render backend URL.
6. Run `flutter pub get`.
7. Run `flutter build apk --release` (or follow `docs/ANDROID_SETUP.md` for an AAB / Play Store build).

## 5. First-deploy verification

1. Deploy backend to Render and wait for "Deploy succeeded".
2. `curl https://<your-render-url>/api/health` — expect `{"ok": true}`.
3. Install the APK on a device. Register a Student account; the email verification link will arrive from Firebase.
4. Sign in → Study tab should appear. Register a second account as General → Study/Groups tabs must be hidden by the bottom-nav.
5. Try Student-only API endpoints (`/api/groups`, `/api/materials`) with the General id-token → expect `403`. The fixture in `backend/tests/test_auth_and_roles.py` asserts this behavior.

## 6. Where to put what (recap)

| Layer | File / env | Provided by you |
| --- | --- | --- |
| Backend secrets | Render env (see §3) | Firebase service account, Supabase service-role key, Gemini key |
| Backend config (URLs, limits) | Render env + `backend/.env.example` (template) | Render env values |
| Flutter backend URL | `flutter_app/lib/core/app_config.dart` | Your Render URL |
| Flutter Firebase config | `flutter_app/lib/firebase_options.dart` | `flutterfire configure` |
| Android Firebase config | `flutter_app/android/app/google-services.json` | Firebase console download |
| Firestore rules | `firebase/firestore.rules` | Already shipped |
| Supabase bucket policy | Supabase dashboard | Private bucket, no public access |

## 7. Things you should NOT change

- `firestore.rules` — already denies client writes to `reports`, `ai_usage`, `upload_usage` and freezes `users/{uid}.role`.
- Backend defaults for `SIGNED_URL_TTL_SECONDS` (900), upload caps (15 MB / 100 MB / 10/day), AI quota (30/day) — set in `backend/app/core/config.py`. Override via env only if your deployment profile requires it.
- AI prompt templates in `backend/app/services/ai_service.py` — they intentionally contain no MCQ / auto-question generation.

## 8. If something breaks

- Backend logs: Render dashboard → service → Logs

- Local Flutter run: `cd flutter_app && flutter run`
- Test suite: `cd backend && python -m pytest tests/ -q` (currently 14/14)
- Static check: `cd flutter_app && flutter analyze` (currently 0 errors, 0 warnings)
