# Database audit

> **Source-of-truth resolution.** Source code wins over README. Active store is **PostgreSQL via SQLAlchemy + Alembic** for CommuteBD and the mirrored tables; **Firebase Firestore** is the live UI store for app data.

---

## 1. Engine + driver

- **Driver:** SQLAlchemy 2.x + `psycopg[binary]` (Postgres) with SQLite in-memory fallback for tests.
- **Source:** `backend/app/database/connection.py`.
- **Connection string:** `app.core.config.DATABASE_URL` (Render env `DATABASE_URL`).
- **Default fallback:** `sqlite:///./gochano.db` (only when `DATABASE_URL` is empty — this is for local-only development; tests override to in-memory).
- **Session:** `SessionLocal` factory; FastAPI dependency `get_db()`.

## 3. CommuteDB schema detail (PostgreSQL)

From `20260829080000_initial_commutebd.py`:

```sql
-- Extensions
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS pg_trgm;

-- Lat/lng as numeric(9,6) (no Geometry columns yet)
ALTER TABLE places
  ADD COLUMN IF NOT EXISTS lat numeric(9,6),
  ADD COLUMN IF NOT EXISTS lng numeric(9,6);

ALTER TABLE routes
  ADD COLUMN IF NOT EXISTS start_lat numeric(9,6),
  ADD COLUMN IF NOT EXISTS start_lng numeric(9,6),
  ADD COLUMN IF NOT EXISTS end_lat   numeric(9,6),
  ADD COLUMN IF NOT EXISTS end_lng   numeric(9,6);

-- Indexes
CREATE INDEX IF NOT EXISTS ix_places_name_trgm ON places USING gin (name gin_trgm_ops);
CREATE INDEX IF NOT EXISTS ix_places_lat_lng  ON places (lat, lng);
CREATE INDEX IF NOT EXISTS ix_routes_lat_lng  ON routes (start_lat, start_lng, end_lat, end_lng);
```

Indexes:

| Index | Type | Purpose |
|---|---|---|
| `ix_places_name_trgm` | GIN (pg_trgm) | Substring / fuzzy name search. |
| `ix_places_lat_lng` | Composite B-tree | Bounding-box pre-filter before Haversine. |
| `ix_routes_lat_lng` | Composite B-tree | Same, for routes. |

**Triggers / functions:** none.

## 4. PostGIS status

| Aspect | Status |
|---|---|
| Extension installed (`CREATE EXTENSION postgis`) | ✅ |
| Extension available to schema | ✅ |
| `geometry` / `geography` columns on application tables | ❌ (numeric only) |
| Spatial index (`GIST` on `geometry`) | ❌ |
| Spatial queries | ❌ — Haversine on numeric `lat`/`lng` |

**Decision:** defer `geometry` columns. At current scale (~10k places) Haversine is sub-10 ms; GIST becomes valuable past ~100k rows. The Phase-2 migration's choice of numeric + trigram + composite B-tree is correct.

## 5. Read patterns

| Operation | Active path | Performance |
|---|---|---|
| Place search (substring) | `places` `SELECT … WHERE name ILIKE %x%` + trigram fallback | Trigram enables substring without leading wildcard. |
| Place nearest | Numeric `(lat, lng)` bbox pre-filter → Haversine sort | Sub-50 ms for 10k rows. |
| Route solve | `routes` join → OSRM/HTTP call → fare model | External network is bottleneck, not DB. |
| Fare report | `fare_reports` insert with deterministic ID | Idempotent. |
| AI conversation history | (Firestore — not Postgres) | — |
| Expense list | (Firestore — not Postgres) | — |
| Task list | (Firestore — not Postgres) | — |
| Group chat | (Firestore — **LEGACY**) | — |
